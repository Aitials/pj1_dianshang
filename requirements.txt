# 后端依赖清单（uv / pip 通用）。本文件是「当前验证可用的虚拟环境」的完整冻结，共 104 个包。
#
# ===== 相对上一版的变化 =====
# 1. 新增 langchain==1.4.3 + langgraph==1.2.13 及其整条编排链
#    原因：AI 助手已从「手写两轮工具循环」迁移到 langchain v1 的 create_agent，
#    app/services/AI.py 会执行 `from langchain.agents import create_agent`。
#    少了它容器启动即 ModuleNotFoundError —— 这正是 Docker 报错的原因。
#    （langgraph-checkpoint / -prebuilt / -sdk 是 langgraph 的硬依赖，一并冻结）
# 2. 新增 langchain-openai==1.6.7 / openai==3.24.0 / tiktoken==0.14.0 / jiter==0.17.0
#    智谱走 OpenAI 兼容端点，ChatOpenAI 是真正调用模型的客户端。
# 3. 新增 rich==15.0.0
#    被 app/services/AI.py 引用（`from rich import print as rprint`）。
# 4. 新增 httpx2 / httpcore2（langsmith 的硬依赖）
#    与已有的 httpx==0.28.1 / httpcore==1.0.9 并存，互不冲突，不要试图合并。
#
# ===== 历史决定（仍然有效，别改回去）=====
# - 不装 zhipuai：它与 zai-sdk 在 PyJWT 上约束互斥
#   （zhipuai 要 pyjwt>=2.8.0,<2.9.0；zai-sdk 要 pyjwt>=2.9.0,<3.0.0，交集为空）。
#   uv 是严格解析器，两个同时出现在本文件里必然解析失败。
# - PyJWT 固定 2.14.0 是为了满足 zai-sdk（联网搜索 query_web 仍在用它）。
#   项目自身的鉴权走 python-jose，不读 PyJWT。
#
# ===== 注意 =====
# 本清单在 Windows + Python 3.14.7 上冻结；容器基础镜像是 python:3.14-slim（Linux）。
# 绝大多数包是纯 Python 或提供 cp314 manylinux wheel。
# 若 docker build 时报 "no matching distribution" 或 "Building wheel for xxx"，
# 说明该包缺 Linux 版 wheel，需要单独处理（换版本或补构建工具）。
#
# 重新生成本文件（会覆盖以上注释）：
#   uv pip freeze > requirements.txt
